# 不明显掉帧：必须说明测了什么

降低面数不能保证帧率：瓶颈可能是CPU提交、过绘制、复杂shader、阴影、透明、物理、脚本、资源加载或设备节流。先定位，再优化。目标是满足用户在**指定设备/场景/设置/时段**的要求，不能承诺任意模型、任意设备永不掉帧。

## 三种测量不能混写

| 类型 | 可说明什么 | 不能替代什么 |
|---|---|---|
| 普通可见Player逐帧墙钟间隔 | 已测窗口中真实帧交付节奏 | 纯GPU耗时、全工程、XR |
| Camera.Render+同步ReadPixels离屏完成间隔 | 对照渲染路径含CPU/GPU同步读回的开销 | 屏幕FPS、纯GPU时间 |
| 有效GPU计时器/Profiler | 该工具/队列范围的GPU工作 | 自动等同CPU、屏幕、XR compositor |

ProfilerRecorder值全0、GPU计时返回null/-1、隐藏窗口不绘制，不得填写成“0开销”。首次快速结果若Draw Calls=0/前景为空，应标INVALID，保留记录并修正fixture。截图操作放在计时窗口之外。

## 实际采集契约

保存硬件、OS、引擎/构建类型、图形API、分辨率、MSAA、管线、色空间、阴影、vsync/FPS上限、电源模式，以及可用的驱动/温度/负载信息。最终以目标Player和设备为准；Editor小试用于筛选。先核实画面真的渲染完整模型：背景非空不够，需对象/活动Renderer、预期像素、draw证据。近景仍需完整板体时，不可只测隔离零件；两者分范围记录。

原版/候选采用交错/回文顺序，例如ABBA；各腿相同预热与计时长度、确定性相机路径，覆盖全板旋转、接近与关键细节停留。至少独立重启复测异常方向。不要只延长有利的一侧；不删除尖峰。初次启动和预热如不计入，报告排除范围。瞬时峰值、持续长帧分别报告。

限60帧时，两方案均约60FPS只能证明都达到该限帧条件，不能据此声称加速百分比；若研究余量，另做明示的不限帧诊断。60FPS理想预算约16.667ms，但操作系统与计时抖动会让少量间隔略过此值；项目采用何种长帧阈值需事先说明，不事后改线让结果通过。

## 统计

每个session、scope/view、arm分别报告N、P50/P95/P99、最大、超过约定阈值的数量、最长连续长帧；平均FPS用`1000*N/sum(frame_ms)`，不是瞬时FPS算术平均。保留原始块、时序和来源哈希。

线性百分位：排序后 `i=(N-1)*q`，在floor/ceil间插值，不能标为线性却用floor(q*N)。可以在同一session/view/arm内池化分布，但连续长帧只在真正连续计时块内部计算。各方向P99的范围不是所有帧池化P99。不同会话、版本、相机、隔离/完整范围不拼成一次完整矩阵。

允许退化例如 `candidateP99 <= originalP99+max(5%*originalP99,0.2ms)` 是本项目历史诊断规则，**不是普适标准**。同时检查新增持续长帧。与绝对目标帧时间、人工观感分列。发现FPC近景退化，即使整板更快也保留失败。一个坏方向不能用大量好方向平均掉。

## 分析器输入协议

`analyze_frames.py`不采集数据；输入必须来自真实采集器或明确标注的合成fixture。按以下结构转换原始数据，保留raw文件哈希和采集器记录。它接受screen、offscreen_sync、gpu三种标识，输出不证明采集标识真实。

```json
{
  "measurement": "screen",
  "environment": {
    "device": "实际设备",
    "resolution": [1920, 1080],
    "fps_cap": 60,
    "render_validity_evidence": "实际画面与有效渲染证据的相对路径",
    "raw_sha256": "真实原始文件SHA256"
  },
  "rows": [
    {"session":"s1","view":"full_orbit","arm":"original","block":"leg0","frame_ms":[16.6,16.8]},
    {"session":"s1","view":"full_orbit","arm":"candidate","block":"leg1","frame_ms":[16.7,16.7]}
  ]
}
```

每行是一段实际连续的计时块；session/view/arm/block组合必须唯一。视角切换、预热、暂停不能偷偷跨接。warmup不放入frame_ms；计时内尖峰全保留。无原版或候选时返回unknown，不能自动通过。无效/非有限/零或负数直接拒绝，不能转0。

脚本`all_measured_comparisons_pass`只是原始样本在所给容差下的描述统计：不验证样本量足够、ABBA顺序、画面真实性、绝对目标、测试场景覆盖、外观或用户验收。`full_acceptance_proven`固定false。人工/更高层检查必须看这些条件。

## 异常定位与停止条件

先排除漏画、错误相机、错误模型/哈希与不同环境，再做保持其他条件一致的单因素消融。删掉shader层的收益是该试验中的边际证据；遮挡变化会影响后续片元，不能直接断言某条指令唯一根因。CPU调用/回退次数不等于实测GPU指令次数。

修复前写推进条件和编译/试验时间上限；没有稳定收益或编译未完成就保留“未验证、不集成”，不持续叠加微调。PNG相同不证明性能相同；性能改善不证明画面对。所有结果绑定准确候选哈希。相同原始文件SHA说明继承数据，不是新版本独立测量。
